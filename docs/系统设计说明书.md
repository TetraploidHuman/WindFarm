# 第1章 概述

## 1.1 作品简介

本作品是一套面向低空复杂动态风场的无人机自主导航系统，软件主体部署于机载边缘计算单元、服务数据处理端与客户端 Web 监视站。系统以固定翼无人机为载体，围绕“物理感知—认知推理—规划决策”三层软件架构，实现风场感知、不确定性管理与全局能耗优化路径规划，通过 4G 链路与地面站形成物联网闭环。

工程实现上，离线评测与算法闭环集中在 Python 包 `windfarm`；实时监视与机载遥测由 `windfarm.rtwind`（FastAPI + WebSocket）及 Android 传感 App 完成。物理感知对应 `physics.py` / `data_ingest.py`，认知推理对应 `ml.py` / `pipeline.py` / `belief.py`，规划决策对应 `planner.py` / `controller.py` / `execution.py`，系统服务对应 `api_server.py` 与 `rtwind/`。

传统无人机路径规划一般基于静态环境假设，也就是以最短直线距离为目标，而忽略了低空动态风场对能耗的影响。本系统利用地形数据对粗尺度气象风场进行物理演算，得到三维的风场数据初始值；再使用 XGBoost 残差学习进行在线修正；通过三维信念地图以贝叶斯滤波管理不确定性；在路径规划时将完成进度引入优化框架，对剩余航线进行优化。实验表明：风速预测 RMSE 降低 69.4%；垂直风预测 MAE 降低 72.3%；在二十个真实地形的历史场景模拟中，相较于最短直线，优化后的路线节约能耗 4.0%，典型场景可达 10.1%。

## 1.2 设计背景与问题界定

随着低空经济的发展，无人机在电力巡检、应急救援、物流配送等场景中的应用日益广泛。低空环境的风场复杂多变，丘陵、山地、海岸等区域的地形诱导局地风场对飞行时能耗影响显著。而传统算法通常将环境视为静态或准静态，以直线距离最短为最优路径，忽略了风场对无人机飞行的影响，限制了作业半径与任务效能。

针对最优能耗路径规划，现有主要方案与局限包括：

（1）纯物理建模，利用 WRF（中尺度天气预报模式）或 CFD（计算流体力学）进行高精度风场模拟[4]，缺点是计算成本极高，无法满足一般用户需求。

（2）纯数据驱动，利用高斯过程回归、深度学习等方法从历史数据中学习风场模式[5]。但该方法泛化能力差，并且缺乏物理约束，可能产生不符合物理规律的预测数据。

（3）感知与决策分离，现有系统即使具备风场感知能力，其感知输出也多用于状态监视或离线分析，并没有以闭环的方式参与到路径规划当中。同时，默认传感数据为可信，忽略了预测不确定性带来的决策风险，导致规划器无法区分可靠信息与不可靠信息。

（4）决策短视，传统分段规划或固定时域模型预测控制（MPC）仅优化未来有限时域内的路径，却未考虑决策对整条航线总能耗的影响，容易陷入局部最优。

## 1.3 作品目标与特色

（1）物理风场与残差学习融合的混合感知：由于低空风场受地形影响显著，粗尺度气象数据由于分辨率不足，无法直接用于航迹规划，而纯数据驱动的方法依赖海量实测样本，并且泛化能力不足。因此，本作品提出了物理先验与数据修正的混合风场感知方法。其原理是利用地形高度数据对粗尺度气象风场进行物理演算，获得具有物理解释性的风场初始值，而后引入 XGBoost 模型，对物理初始值的预测残差 \(\Delta u,\Delta v,\Delta w\) 进行在线修正。此架构既克服了纯物理模型精度不足的问题，也解决了纯数据模型泛化能力弱的瓶颈。源码入口为 `physics.downscale_wind` 与 `ml.ResidualWindModel` / `pipeline.WindFarmPipeline`。

（2）信念地图驱动的不确定性管理：传统路径规划将感知结果视为确定性真值，忽略预测不确定性带来的决策风险。本作品将信念地图扩展至三维动态矢量风场，使用空间网格维护风场均值/方差、上升—中性—下沉三态模式概率，以及能量收益、不确定性与安全惩罚。通过贝叶斯滤波实现先验预测—观测校正的闭环（`belief.BeliefUpdater`），使无人机具备边飞边认知的能力。规划器在高不确定性区域采取保守策略，在低不确定性区域积极利用气流，实现趋利与避害的统一。

（3）进度感知的全路线联合优化：传统分段规划或固定时域 MPC（每次只优化未来固定长度的一小段路径）由于视野有限，未考虑总体进度，容易陷入局部最优。本作品针对传统 MPC 的有限视野问题，将路径完成进度引入优化框架，使规划器能够感知当前决策对完成整条剩余航线总能耗的影响。实现上采用内层有限时域集束搜索 anytime MPC、外层 Dijkstra 返航代价图，并与能量走廊/巡航高度带引导线联合择优（`planner.plan_path_details`）。

（4）完整三层系统与轻量化边缘部署：在系统架构层面，以固定翼无人机为载体，构建感知—服务—应用三层有机耦合的完整系统。感知层集成多个传感器所采集的环境与状态数据；服务层通过 4G 实现机载端与地面站交互；应用层由飞控、边缘计算单元和地面站软件构成决策闭环。仅需在普通无人机上加装轻量级边缘计算单元及少量传感器即可实现全部功能，具备向现有工业无人机平台快速推广的工程条件。

|------|----------|
| 任务操作员 | 在地面站客户端监视飞行态势、查看风场与规划结果 |
| 无人机飞手 | 负责起飞降落，异常时接管飞行 |

表2-2 外部接口对象

| 对象 | 主要功能 |
|------|----------|

| 机载传感器与 GPS | 提供空速、气压、姿态、位置等测量数据 |
| 地形/气象数据 | 为任务规划提供静态地形数据（SRTM1 DEM）和动态气象信息（Open-Meteo 10 m/100 m 风场） |

## 2.2 功能需求

### 2.2.1 飞行数据获取

服务端算法需要持续获取空速、气压、加速度、GPS 等数据，做时间对齐和异常剔除，并融合空速与地速解算出当前局地风矢量，作为后续修正与规划的观测输入。同时需要获取对应地理位置的 DEM 和粗尺度气象风场，为地形相关的风场基线计算提供数据。

实现上，离线观测统一为 `types.Observation`（字段含 `u_obs,v_obs,w_obs,airspeed,ground_speed,climb_rate`）；实时链路由 Android 传感 App 经 `POST /api/ingest` 或优先经 `WS /api/ws/ingest` 注入 `TelemetryHub`，再由 `BeliefRuntime.observe_frame` 转为局地风观测。地形与气象由 `data_ingest.ensure_srtm_tile` / `terrain_from_srtm`、`fetch_open_meteo_hourly` 完成拉取与重采样。

### 2.2.2 风场计算与更新

系统要先利用地形信息对粗风场做物理规律演算，从而得到具有物理解释性的风场初始值；再在初始值之上利用机器模型进行残差修正，以提高对局地扰动的估计精度。飞行过程中根据新的实测数据进行持续更新，并维护各区域估计的可信程度（也就是不确定性）。因此，最终提供给规划模块的，不仅仅是风速，还包括哪里更有把握、哪里风险更大等信息。上述风场相关计算主要在服务端完成，机载侧重提供观测与状态。

对应代码路径为：`physics.downscale_wind` → `ResidualWindModel` 预测残差 → `BeliefUpdater.apply_prediction` / `update_with_observation`，输出 `uncertainty`、`safety_penalty`、`expected_energy_gain` 等规划用派生量。

### 2.2.4 路径规划

路径规划在服务端根据当前任务、飞机状态和风场估计生成航线或控制建议，目标是更省电、更稳妥，而不是只追求几何路程最短。规划过程需要能感知任务完成进度，从而对整段剩余航线进行优化，并支持在风场变化后进行重规划。并且实现不确定性高的区域偏保守、有利风场且较有把握的区域适当绕行借风的效果。规划结果下发到机载微控制器之后，再交由飞控执行。

实现入口为 `planner.plan_path_details`：anytime 束搜索 MPC + Dijkstra 返航代价图 + 直线 AGL / 侧向走廊引导线能量择优；由 `execution.NavigationEngine` 按 `replan_interval_steps` 滚动调用，能耗评估共用 `controller.transition_energy_j`。

### 2.2.5 地面监视

地面站需向用户实时显示空速、地速、高度、姿态、电量、链路等状态，并能看到风场以及不确定性相关信息和规划轨迹，便于判断当前估计与规划是否合理。前端位于 `rtwind/static/`（`app.js`、`quad.js`、`meteo.js`），经 WebSocket `/api/ws` 接收推送。

### 2.2.6 日志记录

飞行过程中自动保存状态、风场观测、规划决策与轨迹等日志，方便事后复盘和继续改进模型。残差模型与主要规划参数可配置，更新算法时尽量不影响采集、飞控接口等无关部分。闭环每步写入 `NavigationContext.trace`，任务结束生成 `mission_report.json`；残差模型以含 `raw_model_b64` 的 `model.json` 版本化管理，超参见根目录 `config.json`。

# 第4章 详细设计说明书

## 4.1 基于物理规律的风场初始值计算

该模块的任务是生成具有物理解释性的风场初始值。由于粗尺度气象风场仅反映大体背景趋势，需要结合 DEM 地形数据做特征提取，从而建立坡度加速、狭管压缩与地形遮蔽等参数化方程，将粗风下推为米级的风场数据。实现文件为 `src/windfarm/physics.py`，入口函数 `downscale_wind(u_km, v_km, terrain, w_km=0, altitude_levels=5, altitude_step_m=50, u_100=None, v_100=None)`，输出形状为 `(Z,H,W)` 的 `WindField(u,v,w)` 及诊断量 `PhysicsDiagnostics(f_elev,f_rough,f_slope,delta_elev)`。

处理步骤：

S1 地形特征提取：从 DEM 计算坡度、坡向、局地高差、粗糙度（`data_ingest.terrain_from_srtm`）。

S2 水平插值/垂直剪切：将粗风场落到 DEM 网格；有 Open-Meteo 100 m 风时，在各高度层 \(z_{\mathrm{AGL}}=k\cdot\Delta z\) 上对 10 m/100 m 风速风向做对数插值：

\[
t_{\mathrm{shear}}=\mathrm{clip}\!\left(\frac{\ln\max(z,10)-\ln 10}{\ln 100-\ln 10},0,1\right).
\]

S3 地形修正：相对高差 \(\Delta h=h-\bar{h}\)，坡向相对来风角 \(\theta\)，修正因子为

\[
\begin{aligned}
f_{\mathrm{elev}}&=\mathrm{clip}(1+0.0015\,\Delta h,\,0.7,\,1.3),\\
f_{\mathrm{rough}}&=\mathrm{e}^{-0.4\,r},\\
f_{\mathrm{slope}}&=\mathrm{clip}(1+0.5\,s\cos\theta,\,0.6,\,1.4).
\end{aligned}
\]

水平风速再乘粗糙度衰减 \(\mathrm{e}^{-1.2\,r(1-0.6\rho)}\) 与剪切增益（有 100 m 风时 \(0.02+0.04\rho\)，否则 \(0.08+0.18\rho\)）；分量按气象约定 \(u=-V\sin\psi,\;v=-V\cos\psi\)。

S4 垂直风速估计：由地形抬升 \(\mathrm{upslope}=s\cos\theta\)、脊波 \(\mathrm{ridge\_lift}=s\sin^2\theta\) 与粗糙耗散估计 \(w\)，并裁剪到 \([-3.5,4.5]\) m/s：

\[
\begin{aligned}
w=\mathrm{clip}\big(&
w_{\mathrm{km}}(0.9-0.2\rho)
+2.4(1-0.45\rho)\,\mathrm{upslope}
-(0.9-0.35\rho)\,r\\
&+g_{\mathrm{wave}}\,0.6\,\mathrm{ridge\_lift}
+0.0012\,\Delta h+0.25\rho,\;-3.5,\;4.5\big).
\end{aligned}
\]

S5 输出：米级三维风场基线及修正因子。

关键实现片段：

## 4.2 预测残差修正与信念地图更新

单纯的物理模型难以对所有场景都进行准确演算，因此，本系统构造多源特征向量（位置、海拔、地形、粗风、物理基线、时间与短时历史观测），以 XGBoost 机器学习回归物理初始值残差。相较 WRF/CFD、高斯过程与深度网络，XGBoost 更适合小样本、多维非线性与可解释特征重要性需求。

实现上，`pipeline.FEATURE_NAMES` 共 62 维，涵盖：空间高度（`x_norm,y_norm,z_norm,altitude_m`）、地形（`elev,slope,aspect,aspect_sin/cos,roughness,terrain_wave_*,lee_wave_*`）、粗风与物理基线（`u_km,v_km,w_km,u_phy,v_phy,w_phy,f_slope,f_rough,delta_elev`）、时间周期项，以及 `PredictSession` 维护的短时历史（`prev_*_km,delta_*_km,prev_local_*,local_trend_*,prev2/3_*,*_mean`）。训练目标为观测相对物理初始值的残差：

\[
y_u=u_{\mathrm{obs}}-u_{\mathrm{phy}},\quad
y_v=v_{\mathrm{obs}}-v_{\mathrm{phy}},\quad
y_w=w_{\mathrm{obs}}-w_{\mathrm{phy}},
\]

最终风场预测为“物理基线与残差修正” \(\hat{u}=u_{\mathrm{phy}}+\Delta u\)（\(v,w\) 同理）。`ResidualWindModel` 对 \(u,v,w\) 分训三个回归器；默认 `config.json` 中 `model_type=xgboost`，`num_estimators=96`，`max_depth=3`，`learning_rate=0.1`，`feature_subsample_ratio=0.55`，`max_training_samples=4000`，`early_stopping_rounds=12`，`temporal_window_size=4`；XGBoost 不可用时回退 LightGBM → 自研 GBRT → Ridge。特征重要性与性能对比如图4-1、图4-2所示。

三维信念地图将空域划分为网格，每格存储风场高斯分布（均值与协方差），并维护能量收益、不确定性与安全惩罚。实现文件为 `belief.py`：`create_belief_map` / `create_scoring_belief_map` 分配网格；`field_arrays` 键包括 `wind_u/v/w`、`wind_var_u/v/w`、`wind_cov_uv`、`mode_prob_sink/neutral/uplift`、`belief_entropy`、`uncertainty`、`hazard_prob`、`safety_penalty`、`expected_energy_gain`、`confidence`、`last_update`。滤波超参默认：`observation_radius=2`，`advection_gain=0.25`，`decay_per_step=0.04`，`process_noise=0.18`，`observation_noise=0.12`，`advection_noise=0.08`。

更新流程：

A1 先验推进并加入过程噪声：按未更新年龄 \(\sigma^2\leftarrow\min(4,\sigma^2+q(1+\lambda\cdot\mathrm{age}))\)；模式概率经马尔可夫转移（近似 \(s\!:\!0.72/0.18/0.06\)，\(n\!:\!0.20/0.64/0.20\)，\(u\!:\!0.08/0.18/0.74\)）再归一化；再与先验信念做 Kalman 式融合（冷启动增益=1，新近观测与剪切边缘抵抗覆盖）。

A2 空速计+GPS 解算观测：`energy_gain=0.5*(ground_speed-max(airspeed,0))+climb_rate`。

A3 对邻近网格贝叶斯后验校正：影响半径内 `influence=max(0,1-d/(R+1))`，水平风 2×2 Kalman（含 `cov_uv`），垂直分量标量 Kalman；模式观测由 \(w\) 与能量收益 logistic 得到后与先验混合；可选沿风向平流 1～3 格。

A4 更新安全惩罚与期望能量：

\[
\begin{aligned}
U&=\overline{\sigma^2_{uvw}}+0.25\,H(\mathrm{modes}),\\
S&=0.52\,H_{\mathrm{haz}}+0.28\,\mathrm{clip}(U/3)+0.20\,\mathrm{clip}(\max(-w,0)/2.5),\\
E&=0.55\max(w,0)-0.85\max(-w,0)+1.25\,P_u-0.95\,P_s-0.28\,S.
\end{aligned}
\]

该机制支持陌生区域先依物理基线飞行，再随观测收缩不确定性。校准关系如图4-3。实时端 `BeliefRuntime` 默认 10 km×10 km @ 50 m → 201×201 网格。

## 4.3 具有进度感知的路径规划

将“路径完成进度”作为状态变量引入 MPC，增广状态含位置、航向、空速与向目标推进量，使优化覆盖剩余全程而非固定短时域。目标综合能耗、风场收益、进度奖励、风险成本、高度带/能量走廊惩罚与终端代价。求解采用分层策略：内层有限时域集束搜索 anytime MPC，外层 Dijkstra 返航代价图提供全局可行性，并与直线 AGL / 侧向走廊引导线按 `transition_energy` 择优。

规划与执行共用能量模型 `controller.transition_energy_j`：逆风项 \(\mathrm{headwind}=-\hat{u}\cdot V_h-0.2\,w\)，功率含巡航/酒店负载、逆风惩罚、顺风与上升气流减免、爬升代价等，再乘抬升缩放 \(\mathrm{uplift\_scale}(w)\in[0.5,1.4]\)。飞行包线空速约 8.5～22 m/s；MacCready 式空速对逆风增益约 0.85。返航预算为 `battery_j - reserve_energy_ratio·capacity`（默认储备比 0.22）。

求解步骤：

S1 构建 Dijkstra 返航代价图（`compute_return_cost_map`，宽网格可用 `xy_stride=2`）。

S2 离散剩余航线候选节点并计算能量代价；并行生成 `_energy_guide_paths`（多巡航带直线与侧向走廊）。

S3 在能量走廊与高度带内集束搜索展开状态：`anytime_rounds=4`，启发式权重由 2.4 线性降到 1.0；`horizon_steps=7`，`beam_width=28`，`branch_width=10`，`search_node_budget=9000`，折扣因子 \(\gamma=0.93\)，终端进度奖励 `terminal_progress_weight=24`。价值更新为 `value += γ^depth * step_reward`，达目标再加终端奖励。控制原语含 approach/cruise/energy_save、侧向探测与热气流盘旋。

S4 用信念地图评估风场收益与不确定风险：离散转移代价

\[
C=E_{\mathrm{trans}}-R_{\mathrm{progress}}+22\cdot\lambda_{\mathrm{risk}}\cdot U+28\cdot\lambda_{\mathrm{safe}}\cdot S+C_{\mathrm{alt}}+C_{\mathrm{vert}},
\]

其中默认 `risk_weight=1.2`、`safety_weight=1.5`。

S5 联合优化输出控制序列；比较 MPC 与各引导线能量，写回 `preferred_cruise_agl` / `guide_via`。

S6 执行首步控制并滚动重规划。闭环一步（`NavigationEngine.step`）顺序为：风场预报 → `apply_prediction` → 可选观测更新 → 高不确定侧向探针 → truth∩belief 双同意蒸馏 → `_replan` → `_move_if_possible` → 写 trace。进度 ≥0.85 时强制贴合直线 AGL 引导下降，抑制近目标抖动。

# 第7章 用户操作手册

## 7.1 起飞前准备

检查无人机结构、动力、电池电量与传感器连接；确认空速计、GPS、4G 模块工作正常。

上电飞控与边缘计算单元，确认边缘程序自启并完成传感器自检。

地面站电脑接入网络，打开监视台页面，确认遥测链路指示为已连接。

下载或加载任务区 DEM/气象预下载包，设置起点、终点与任务航点。

选择模拟模式先跑通任务，再切换真机模式。

本地无真机时可先跑通算法演示：

```bash
python -m pip install -e .
python -m windfarm.cli generate-config --output config.json
python -m windfarm.cli run-demo --config config.json --runs-dir runs --run-name latest
python -m windfarm.cli build-dashboard --report runs/latest/mission_report.json --output dashboard.html
```

## 7.2 任务执行

在监视台确认规划就绪后，按飞控规程起飞并切入自动航线。

如需调整任务，可通过地面站下发参数或更新航点；机载将滚动重规划。

# 第10章 总结与展望

本说明书给出了可部署的风场感知与路径规划导航软件的需求、概要/详细设计、数据与界面、操作与安装及评测结果。详细设计章节已与仓库实现（`physics` / `ml` / `belief` / `planner` / `execution` / `rtwind`）对齐，便于对照源码验收。系统可服务于电力巡检、应急救援、植保与复杂地形科考等低空场景，在同等电量下有望延长有效作业半径约 3%–4%，并随飞行架次累积持续改善信念地图。

后续可继续优化物理基线置信度评估、信念地图多分辨率表示、传感器噪声在线估计与通信降级自主策略，并推进从仿真到实机的渐进验证。
