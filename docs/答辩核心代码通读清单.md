# 答辩核心代码通读清单

面向程序设计大赛答辩分工：机器学习负责人与嵌入式负责人优先通读下列核心文件。  
说明：仓库中「智能」侧为 XGBoost 残差风场模型（非深度学习框架）；嵌入式侧以 Android 机载传感 + MAVLink 接入为主。

---

## 一、机器学习（5 个）

| 路径 | 作用 |
|------|------|
| `src/windfarm/ml.py` | 残差模型本身 |
| `src/windfarm/pipeline.py` | 特征 + 训练/预测 |
| `src/windfarm/physics.py` | 物理基线（残差改什么） |
| `src/windfarm/belief.py` | 信念场融合 |
| `src/windfarm/execution.py` | 预测→信念→规划闭环 |

补一眼：`src/windfarm/planner.py`（用信念做路径）

建议阅读顺序：`ml.py` → `pipeline.py` → `physics.py` → `belief.py` → `execution.py` → `planner.py`。

---

## 二、嵌入式（5 个）

| 路径 | 作用 |
|------|------|
| `android/rtwind-sensor/.../sensor/TelemetryAggregator.kt` | 传感融合上报 |
| `.../sensor/ImuTracker.kt` + `LocationTracker.kt` | IMU / GPS（可当一对） |
| `.../service/TelemetryService.kt` | 机载持续采集 |
| `src/windfarm/rtwind/mavlink_source.py` | 飞控 MAVLink |
| `src/windfarm/rtwind/live_source.py` | 手机 HTTP 接入 |

补一眼：`src/windfarm/rtwind/hub.py`（遥测汇聚）

Android 包路径前缀一般为：  
`android/rtwind-sensor/app/src/main/java/.../`（以仓库内实际包目录为准）。

建议阅读顺序：`TelemetryAggregator` → IMU/GPS → `TelemetryService` → `mavlink_source` → `live_source` → `hub`。

---

## 三、两人共同核心（2 个）

| 路径 | 作用 |
|------|------|
| `src/windfarm/rtwind/app.py` | 数据进来后怎么进信念/规划 |
| `src/windfarm/rtwind/types.py`（对照 Android `Models.kt`） | 协议字段 |

---

## 四、答辩时注意

- 当前 rtwind 实时链路尚未直接加载 `model.json` 做 XGBoost 推理；残差模型主要在离线/API 任务管线中。
- 相机链路目前是遥测展示，不是视觉深度学习。
- 飞控 / Pico2 等边缘部署细节多见于 `docs/系统设计说明书.md`，仓库内无 MCU 固件源码。
